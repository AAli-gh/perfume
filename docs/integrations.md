# اتصال سرویس‌ها: پیامک، ایمیل، ارسال و گزارش فروش

زیرساخت این چهار بخش ساخته و تست شده است. بعد از ساختن حساب در هر سرویس، فقط مقادیر آن را در `.env` یا پنل مدیریت وارد کنید. کدنویسی لازم نیست.

| بخش | جای تنظیم | بدون تنظیم چه می‌شود |
|---|---|---|
| پیامک (اطلاع‌رسانی سفارش و کد ورود) | `.env`: `SMS_PROVIDER`، `SMS_API_KEY`، `SMS_SENDER` | پیامکی ارسال نمی‌شود و در «گزارش پیام‌های ارسالی» با وضعیت «ناموفق» ثبت می‌شود. سفارش‌ها عادی ثبت می‌شوند. |
| ایمیل سفارش | `.env`: `EMAIL_URL`، `DEFAULT_FROM_EMAIL` | ایمیل ارسال نمی‌شود و خطا در همان گزارش ثبت می‌شود |
| روش‌های ارسال و کد رهگیری | پنل مدیریت ← ارسال ← روش‌های ارسال | هزینه ثابت «تنظیمات فروشگاه» استفاده می‌شود (رفتار قبلی) |
| گزارش فروش | آماده است: استودیو ← گزارش فروش | — |

---

## ۱. پیامک

### گام ۱: حساب سرویس پیامک

یکی از سرویس‌های پشتیبانی‌شده:

| سرویس | `SMS_PROVIDER` | `SMS_API_KEY` | `SMS_SENDER` |
|---|---|---|---|
| کاوه‌نگار | `kavenegar` | پنل ← تنظیمات ← API Key | شماره خط اختصاصی، مثل `10004346` |
| SMS.ir | `smsir` | پنل ← برنامه‌نویسان ← کلید API | شماره خط (فقط عدد)، مثل `30007732` |
| کنسول (فقط توسعه) | `console` | — | — |

حالت `console` پیامک را فقط در لاگ می‌نویسد و در محیط توسعه پیش‌فرض است.

### گام ۲: `.env`

```bash
SMS_PROVIDER=kavenegar
SMS_API_KEY=کلید-API-پنل
SMS_SENDER=10004346
```

سرویس را دوباره راه‌اندازی کنید (`docker compose -f docker-compose.prod.yml up -d`).

### گام ۳: تنظیمات اطلاع‌رسانی

پنل مدیریت ← **اطلاع‌رسانی (پیامک و ایمیل) ← تنظیمات اطلاع‌رسانی**:

- **ارسال پیامک / ارسال ایمیل:** خاموش و روشن کردن هر کانال
- **موبایل مدیران / ایمیل مدیران:** گیرنده‌های «سفارش جدید». چند مورد را با کاما جدا کنید.
- **ورود با کد پیامکی:** فعال کردن ورود با شماره موبایل (بخش ۲)

برای امتحان اتصال، فروشگاه را انتخاب کنید و از منوی عملیات «**ارسال پیامک آزمایشی به موبایل مدیران**» را اجرا کنید. پیام موفق یا خطای سرویس (مثلاً «کلید نامعتبر» یا «اعتبار ناکافی») همان‌جا نمایش داده می‌شود.

### گام ۴: متن پیام‌ها

پنل مدیریت ← **پیام‌ها (متن و الگوها)**. برای هر رویداد، کانال و گیرنده یک ردیف وجود دارد:

| رویداد | پیش‌فرض |
|---|---|
| ثبت سفارش | پیامک و ایمیل به مشتری، پیامک و ایمیل به مدیران |
| پرداخت سفارش | پیامک و ایمیل به مشتری |
| در حال آماده‌سازی | پیامک (خاموش) |
| ارسال سفارش | پیامک و ایمیل همراه **کد رهگیری و پیوند پیگیری** |
| تحویل سفارش | پیامک (خاموش) |
| لغو سفارش | پیامک و ایمیل به مشتری |
| کد ورود یک‌بارمصرف | پیامک |

**متغیرهای متن:** `{store}` `{name}` `{number}` `{total}` `{status}` `{payment_method}` `{shipping_method}` `{tracking_code}` `{tracking_url}` `{order_url}` `{phone}`. برای کد ورود: `{code}` و `{minutes}`. متغیر ناشناخته هنگام ذخیره رد می‌شود.

### پیامک الگو (Pattern)

سرویس‌های ایرانی پیامک **خدماتی** (کد ورود، یا ارسال به شماره‌هایی که تبلیغات را مسدود کرده‌اند) را فقط با **الگوی تأییدشده** می‌فرستند. پس برای کد ورود حتماً الگو بسازید.

1. در پنل سرویس پیامک یک الگو بسازید و تأییدش را بگیرید.
2. در ردیف همان پیام:
   - **کد الگو:** کاوه‌نگار: نام الگو. SMS.ir: شناسه عددی قالب.
   - **متغیرهای الگو:** نام متغیرها به **همان ترتیب الگو**، با کاما. مثلاً کد ورود: `code`. ثبت سفارش: `number,total`.

| سرویس | نمونه متن الگو در پنل | «متغیرهای الگو» |
|---|---|---|
| کاوه‌نگار | `کد ورود شما: %token` | `code` |
| کاوه‌نگار | `سفارش %token به مبلغ %token2 ثبت شد` | `number,total` |
| SMS.ir | `کد ورود شما: #CODE#` | `code` |
| SMS.ir | `سفارش #NUMBER# به مبلغ #TOTAL# ثبت شد` | `number,total` |

- **کاوه‌نگار:** مقادیر به ترتیب در `token`، `token2`، `token3`، `token10` و `token20` قرار می‌گیرند. در سه‌تای اول فاصله مجاز نیست و فاصله‌ها خودکار به نیم‌فاصله تبدیل می‌شوند.
- **SMS.ir:** نام هر پارامتر با حروف بزرگ همان نامی است که در قالب پنل نوشته‌اید (`code` ← `CODE`).

### گزارش و تلاش دوباره

- **گزارش:** پنل مدیریت ← **گزارش پیام‌های ارسالی**. هر پیام با گیرنده، وضعیت، شناسه پیام سرویس و خطا ثبت می‌شود. متن کد ورود هرگز ذخیره نمی‌شود.
- **تلاش دوباره:** پیام ناموفق تا ۳ بار، با فاصله ۲ دقیقه، خودکار دوباره ارسال می‌شود (worker مربوط به Celery لازم است).
- **بدون تکرار:** پیام موفق هرگز دوباره ارسال نمی‌شود.

## ۲. ورود با کد پیامکی

1. سرویس پیامک را طبق بخش ۱ تنظیم کنید و برای «کد ورود یک‌بارمصرف» الگو بسازید.
2. در «تنظیمات اطلاع‌رسانی» گزینه **ورود با کد پیامکی** را روشن کنید.
3. در صفحه ورود دکمه «ورود با کد پیامکی» ظاهر می‌شود (`/account/otp/`).

رفتار:
- **حساب:** شماره‌ای که حساب ندارد، با همان شماره حساب می‌گیرد. شماره‌ای که حساب دارد (فیلد «موبایل» کاربر)، وارد همان حساب می‌شود.
- **کد:**
  - ۶ رقمی است و ۲ دقیقه اعتبار دارد.
  - ۵ تلاش اشتباه کد را باطل می‌کند.
  - هر شماره در ۱۰ دقیقه حداکثر ۳ کد می‌گیرد و هر IP حداکثر ۱۰ کد.
- **امنیت:** فقط hash کد نگه داشته می‌شود. ارسال‌ها و ورودها در «گزارش رویدادهای امنیتی» ثبت می‌شوند.
- **شماره تکراری:** اگر چند حساب یک شماره داشته باشند، ورود پیامکی رد می‌شود و کاربر باید با ایمیل وارد شود.

## ۳. ایمیل سفارش

```bash
EMAIL_URL=smtp+tls://نام-کاربری:رمز@smtp.example.com:587
DEFAULT_FROM_EMAIL=فروشگاه <no-reply@shop.example.com>
```

- **ارسال:** ایمیل‌ها به نشانی‌ای می‌روند که مشتری در فرم تسویه وارد کرده است. اگر خالی باشد، ایمیلی ارسال نمی‌شود.
- **محتوا:** هر ایمیل دو نسخه HTML و متنی دارد و اقلام، مبالغ، کد رهگیری و پیوند سفارش را شامل می‌شود.
- **قالب:** `themes/base/templates/emails/order_event.html` و `.txt`. پوسته‌ها می‌توانند آن را override کنند.
- **موضوع:** در «پیام‌ها» برای هر رویداد قابل تغییر است.

## ۴. روش‌های ارسال و کد رهگیری

پنل مدیریت ← **ارسال ← روش‌های ارسال** ← افزودن:

| فیلد | توضیح |
|---|---|
| عنوان و توضیح | به مشتری نمایش داده می‌شود: «پست پیشتاز · ۳ تا ۵ روز کاری» |
| هزینه پایه | تومان |
| نرخ استان‌ها (جدول پایین فرم) | هزینه متفاوت برای استان‌های مشخص |
| رایگان برای سفارش‌های بالای | مبلغ پس از تخفیف. خالی یعنی هیچ‌وقت رایگان نیست. |
| فقط این استان‌ها | برای پیک شهری فقط استان خودتان. هیچ‌کدام یعنی همه. |
| الگوی پیوند پیگیری | آدرس صفحه پیگیری شرکت حمل که `{code}` با کد رهگیری جایگزین می‌شود. باید با `https://` شروع شود. |
| اولویت / فعال | ترتیب نمایش در صفحه تسویه |

- **در تسویه:** مشتری روش ارسال را انتخاب می‌کند. با انتخاب استان، هزینه و مبلغ نهایی همان لحظه به‌روز می‌شوند. روشی که به استان مشتری ارسال نمی‌کند پذیرفته نمی‌شود.
- **بدون روش ارسال فعال:** «هزینه ارسال» و «ارسال رایگان» تنظیمات فروشگاه استفاده می‌شود.
- **کد رهگیری:**
  1. در سفارش، «کد رهگیری مرسوله» را وارد و ذخیره کنید.
  2. وضعیت را به «ارسال شده» تغییر دهید.
  3. پیامک و ایمیل ارسال با کد و پیوند پیگیری برای مشتری فرستاده می‌شود. کد در صفحه سفارش مشتری هم نمایش داده می‌شود.

### اتصال API شرکت حمل (پست، تیپاکس، …)

وقتی حساب API و مستندات شرکت حمل را گرفتید، اتصال یک کلاس است. سفارش، سبد و قیمت‌گذاری تغییری لازم ندارند:

```python
# apps/shipping/carriers/tipax.py
import requests

from .base import Carrier, CarrierError, Shipment
from .registry import register


@register
class TipaxCarrier(Carrier):
    code, label, supports_api = "tipax", "تیپاکس (API)", True

    def quote(self, *, province, amount):          # اختیاری؛ None = جدول نرخ روش ارسال
        ...

    def create_shipment(self, order):              # اختیاری؛ ثبت مرسوله و گرفتن کد رهگیری
        ...  # self.method.api_key / api_secret / account_id
        return Shipment(tracking_code="...")
```

1. ماژول را در `apps/shipping/carriers/__init__.py` import کنید.
2. در روش ارسال، «شرکت حمل» را `tipax` بگذارید و کلید API، رمز API و شناسه حساب را وارد کنید.
3. با mock کردن پاسخ API تست بنویسید. نمونه در `apps/shipping/tests/test_shipping.py` هست.

> اتصال API پست و تیپاکس هنوز نوشته نشده است، چون مستندات و حساب آزمایشی آن‌ها لازم است. تا آن زمان روش «دستی» (جدول نرخ و کد رهگیری دستی) کامل کار می‌کند.

## ۵. گزارش فروش

استودیو ← **گزارش فروش** (`/studio/reports/`). مجوز لازم: `orders.view_order`.

- **بازه:** ۷، ۳۰ یا ۹۰ روز، یا یک سال، همراه با مقایسه با دوره قبل.
- **کارت‌ها:** فروش، تعداد سفارش، میانگین هر سفارش، کالای فروخته‌شده، تخفیف و تعداد لغوشده
- **نمودار:** فروش روزانه. روی هر ستون مبلغ و تعداد سفارش آن روز نمایش داده می‌شود و جدول روزانه هم زیر نمودار هست.
- **جدول‌ها:** پرفروش‌ترین محصولات، وضعیت سفارش‌ها، روش پرداخت، کدهای تخفیف
- **CSV:** دکمه «دریافت فایل CSV سفارش‌ها» همه سفارش‌های بازه را برای Excel خروجی می‌دهد.
  - فارسی درست نمایش داده می‌شود.
  - مقدارهایی که با `=` یا `+` شروع شوند خنثی می‌شوند تا به‌صورت فرمول اجرا نشوند.
  - هر خروجی در گزارش امنیتی ثبت می‌شود.

**تعریف فروش:** سفارش‌هایی که لغو نشده‌اند، به این شرط که یا پرداخت شده باشند یا روش پرداختشان کارت به کارت یا پرداخت در محل باشد. سفارش آنلاینی که پرداختش تمام نشده فروش حساب نمی‌شود.
